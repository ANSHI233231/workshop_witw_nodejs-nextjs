In short: safari operators (**partners**) apply on the website. The Super Admin approves them, and they build packages and photo galleries in a new **Partner portal**. Every package version and every gallery is approved by the Super Admin before it is used. On the website, users browse packages and parks and send a **quote request** to the package's partner. Nothing is paid in the app.

### 2.3 Rules the services enforce (summary of the workflow and the boards)

- **Partner request (§2):**
  - One request per account. Business name and owner name are up to 255 characters. Business phone is 10 digits starting 6–9 (`INDIAN_MOBILE_PATTERN`). Business email must be valid. At least one **active** park. About is optional (length: Q7). Logo is JPG, JPEG, PNG or WEBP, up to 1 MB, checked from the bytes.
  - A guest's account details follow Sign Up's rules (the app's: name, unique email, unique mobile, password 8–72), and the account, sign-in and request are created in one operation.
  - Rejected → the user edits and sends again (back to Pending, reason cleared). No notification on a new request.
  - Approve → status Active, the **Partner** role is added, and the parks are the request's. Deactivate / activate flips the status. A partner is never deleted.
- **Portal access (§2.1):** anyone with an account signs in. What they see depends on their request: none → the business form; Pending / Rejected → the status page; Inactive → only the deactivated message; Active → the full portal. Every portal API call checks "active partner, and the item is their own".
- **Package (§4):**
  - Basic is saved first and creates the package with **v1 Draft**; sections 2–5 open after that. Each section is saved on its own.
  - The slug is made from the name at creation (`-2`, `-3` when taken, as the board) and never changes.
  - Field rules are the workflow's §4.1–§4.5, with the board's messages. Lowering the number of days asks for confirmation, then removes the extra day blocks (#5); raising it adds empty blocks.
  - Meals → Included ticks every day's three meals; the days can still be changed afterwards.
  - Package and banner images: JPG, JPEG or PNG up to 250 KB. Day image: any size. With no package image, the main park's image is used. The main park is the first park chosen (#4).
- **Versions (§5):**
  - At most one live and one working version. Editing a live package copies it into a new Draft; the live version stays on the website until the copy is approved.
  - Send works from Draft or Rejected and notifies every Super Admin. Delete discards the working version (the package too, if it was never live).
  - Approve: the old live version becomes Replaced, the website status becomes Active (unless Deleted), Popular is cleared, and the first approval sets `first_live_at` (the "Newest" sort).
  - Reject needs a reason, which is shown on the package. The partner is not notified of a decision.
- **Website status (§6):** the partner makes a live package inactive or active at once, with no approval. The Super Admin deletes with an **active** delete reason and details; that is final, and Popular is cleared. Popular can be set only on a live, not-deleted package; Best deal on any package that isn't deleted.
- **Shown on the website** only when all three hold: the package has a live version, its website status is Active, and its partner is Active. The package page link of a package never live goes to the home page. Inactive, Deleted, or a deactivated partner shows "Package Not In Use!".
- **Gallery (§7):**
  - Title (≤255) and one of the partner's own active parks are required. Photos are JPG, JPEG or PNG up to 8 MB, with optional title (≤255) and caption. Replace, remove, reorder. The thumbnail is the first photo by default, can be another, and can't be removed.
  - Save keeps a Draft. Send needs at least one photo and notifies the Super Admins; Waiting can be moved back to Draft. Approve; reject (reason) → Draft with the reason.
  - Editing an approved gallery makes a draft set of photos while the approved set stays in use. Deleting that draft restores the approved set exactly; a gallery never approved is discarded. The Super Admin deletes with a reason up to 512 characters.
  - A package (and each day) attaches a whole approved gallery of any park and keeps a **copy** of its photos as they were when saved (§7.2).
- **Package list and park pages (§8, §10):**
  - Filters: name, park, price per person (₹50,000+ = no upper limit), nights (10+), safaris (10+), stay, features and inclusions (any match). Each chosen filter is a chip.
  - Sorts: Popular (default: popular first, then newest), Newest, Fewest safaris, Most safaris, Price low to high. 12 per page, with more on scroll.
  - Park list: active parks; search, region, A–Z / Z–A; 12 per page. Park page tabs: Overview, Packages (the list's filters except park and search), and Shared Safaris (the same set the Shared Safari list shows).
- **Quote request (§9):**
  - Only for a signed-in user who is not a partner, on a shown package. Travellers 1–100; start date from today (IST); notes required, up to 1,000.
  - Saved with the user's name, email and mobile and the live version, and the partner is notified. No limit on the number.
  - The partner sees their active requests and marks Hot or Cold; clicking the same mark again clears it (#8). They see the phone only when the Super Admin turned on Show phone numbers, and never the email.
  - The Super Admin makes a request inactive or active (inactive hides it from the partner and the user) and sends the partner a free-text notification, up to 255 characters (#10).
- **Notifications (§11), in-app only:** package version sent → Super Admins; gallery sent → Super Admins; new quote request → the partner; Super Admin message → the partner. Four new kinds in the package / gallery / quote hundreds, each with a template row in the migration.
- **Shared Safari impact (§2.5):** from approval on, also while Inactive:
  - A partner is shown by business name and logo: header, account menu, and every comment and reply, including Shared Safari discussions.
  - A partner can't organise or join a new shared safari, but keeps the ones from before and can still comment on them.
  - The account menu gets a **Partner portal** link.
  - These change the shipped Shared Safari screens W1–W4 and W9 (TC-PKSS).
